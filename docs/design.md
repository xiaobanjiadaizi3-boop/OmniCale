# OmniCale 設計メモ

多機能電卓アプリ。「答えだけ出す電卓」ではなく、**解き方をフォルダツリーで掘れる電卓**を差別化点に置く。

---

## 進め方（フェーズ）

| Phase | 内容 | 状態 |
|---|---|---|
| 0 | 土台（monorepo、TypeScript、Vitest、core/ui 分割） | 完了 |
| 1 | 数の表現（厳密値、正規化、全表現の展開、任意精度の小数化） | 完了 |
| 2 | 式とパーサ（AST、トークナイザ、プリティプリンタ、評価器） | 未着手 |
| 3 | 基本電卓 UI（キーパッド、履歴、結果カード）← 最初のリリース | 未着手 |
| 4 | 書き換えエンジンとトレース（Rule、`ctx.frame()`、Step ツリー） | 未着手 |
| 5 | ツリー UI（差分ハイライト、詳細パネル、深さプリセット） | 未着手 |
| 6 | 戦術を増やす（因数分解、一次・二次方程式、別解タブ） | 未着手 |
| 7+ | 実用計算（税・割引・割り勘）→ 単位変換 → 関数電卓 → グラフ | 未着手 |

### 進め方のルール

- **`core` は UI に依存させない。** 例外を 1 つ作ると崩れる。
- **各 Rule / Representation は必ずテストとセット。** ツリーは期待 JSON を丸ごと比較するゴールデンテストが効く。
- Phase 3 で一度リリースし、机上の設計だけで進まないようにする。
- 誤差と精度の扱いは Phase 1 で決めきる。ここだけは後から直せない。

## Phase 1: 値の表現（実装済み）

### 中心となる決定

**計算コアは厳密値 (`Exact`) のまま計算を進め、小数化は表示の直前だけで行う。**

途中で一度でも小数にすると、

1. 誤差が乗る
2. 他の表現（分数・度数法・π 倍表記）に戻せなくなる

の 2 つが同時に起きる。後から差し替えると計算コア全体の書き直しになるため、最初に決めきった。

```ts
type Exact =
  | { kind: 'rational'; value: Rational }              // 有理数
  | { kind: 'radical'; a: Rational; b: Rational; c: bigint } // a + b√c
  | { kind: 'pi'; coeff: Rational }                    // coeff × π
```

不変条件（正規化）により「同じ値なら必ず同じ表現」になるので、構造比較がそのまま等値比較になる。

- `Rational`: `d > 0`、`gcd(|n|, d) = 1`
- `radical`: `c` は平方因子を持たない 2 以上の整数、`b ≠ 0`
- `pi`: `coeff ≠ 0`

### 「全部のパターン」を出す仕組み

1 つの値に複数の等価な表現があるので、値と表示を分離し `representations()` で列挙する。

| 値の種類 | 出る表現 |
|---|---|
| 有理数 | 厳密値 / 帯分数 / 循環小数 / 百分率 / 小数 / 科学表記 / 工学表記 |
| 二次無理数 | 厳密値 / 有理化する前 / 小数 / 近似分数 / 科学表記 / 工学表記 |
| π の倍数 | 厳密値 / 度数法 / 度分秒 / π 倍表記 / 小数 / 近似分数 / 科学表記 / 工学表記 |

各表現は `isExact` を持ち、**UI は `=` と `≈` を厳密に使い分ける**。`√2 ≈ 1.41421356` は等号ではない、という区別を値の側が保証する。

ラベルは `labels.ts` の辞書から引く。表示文字列をロジックに直書きしないことで多言語化と表現のブレを防ぐ（`Record` 型なので、ロケールを片方だけ足すと型エラーになる）。

### 実装の要点

- **π**: Machin の公式 `π = 16·arctan(1/5) − 4·arctan(1/239)` を bigint で計算。数百桁まで実用的で、実装が短く検証しやすい。
- **√**: `isqrt` によるニュートン法。`√8 → 2√2` の簡約は構築時に行う。
- **二重根号**: `√(a + b√c) = √x + √y`（`x, y = (a ± √(a²−b²c))/2`）で外す。例: `√(3 + 2√2) = 1 + √2`
- **有理化**: 共役を掛けて分母から √ を除く。`1/(1+√2) = -1 + √2`
- **循環小数**: 筆算を再現し、余りが再登場した位置を循環の開始とする。
- **近似分数**: 連分数の主近似分数。`π ≈ 355/113`、`√2 ≈ 99/70`
- **丸め**: 表示は四捨五入（`round-half-away-from-zero`）。`piScaled` など内部表現は切り捨て。この違いはテストで固定してある。

### 意図的に Phase 1 で扱わないもの

| 項目 | 理由 |
|---|---|
| 複素数（極形式・指数形） | `atan2` の任意精度実装が必要で、三角関数を持つ Phase 2 以降が適切 |
| 対数形 ⇔ 指数形 | 同上 |
| `√2 + √3` のような異なる √ の和 | この 3 種で閉じない。Phase 2 の記号式が担う（該当する演算は `null` を返す） |
| `1 + π` | 同上 |
| 「入力どおりの形」（`√8` と打ったのに `2√2` と出る） | 値からは復元できない。入力の形は Phase 2 の `Expr` 層が保持する責務 |

## Phase 4–5: 解き方ツリー（設計のみ、未実装）

### ツリーはエンジンの副産物にする

「概要を出してから詳細を生成する」のではなく、**書き換えエンジンの呼び出し階層をそのまま記録する**。

- **戦略（根）**: 「二次方程式を解く」
- **戦術（枝）**: 「因数分解する」「展開する」「平方完成する」— 下位の規則を呼ぶ
- **基本規則（葉）**: `(a+b)² → a²+2ab+b²`、同類項をまとめる — これ以上分解できない 1 手

```ts
type Step = {
  title: string;       // ツリーに出る見出し「平方完成する」
  rule: RuleId;        // 根拠となる規則の ID
  before: Expr;        // 変形前
  after: Expr;         // 変形後
  focus: Path[];       // before のどの部分を書き換えたか（差分ハイライト用）
  level: 1 | 2 | 3;    // 概要 / 標準 / 詳細（初期展開の深さ制御）
  children: Step[];    // 空なら葉
}
```

```ts
function expand(e: Expr, ctx: Trace): Expr {
  return ctx.frame('展開する', RULE.EXPAND, e, () => {
    // 中で呼んだ規則が自動的に children になる
  });
}
```

エンジン側は `ctx.frame()` で包むだけ。ツリーの構築を意識しなくてよいので、規則を増やしても UI は変わらない。

### 表示イメージ

`(x+5)(x+2)`

```
▼ 展開する          → x·x + x·2 + 5·x + 5·2
  │ 最初の括弧の各項と2番目の括弧の各項を掛ける
  ├ x を (x+2) の各項に掛ける     → x·x + x·2
  └ 5 を (x+2) の各項に掛ける     → 5·x + 5·2

▼ 式を簡単にする      → x² + 7x + 10
  ├ x·x を x² にする              指数法則  a·a = a²
  ├ 掛け算の順序を整える            x·2 → 2x,  5·x → 5x
  └ 同類項をまとめる               2x + 5x = 7x

解   x² + 7x + 10
```

詳細パネルは **公式と当てはめを並べる**形に固定する。

```
展開する
─────────────────────
 公式    (a + b)² = a² + 2ab + b²
 当てはめ a = x,  b = 3
─────────────────────
 (x + 3)² → x² + 2·x·3 + 3² → x² + 6x + 9
```

### UI の決定事項

- 折りたたみ時も「見出し＋変形後の式」を見せる（閉じたまま流れを追える）
- 差分ハイライト（`focus` を使い、変わった部分だけ色を変える）
- **由来の色付け**: 項がどの括弧から来たかを色で示す。`focus` とは別に `Expr` ノードへ出自 ID を持たせ、書き換えのたびに引き継ぐ必要がある。**後付けが非常に面倒なので、Phase 2 で `Expr` を定義する時点で入れる。**
- 深さプリセット（概要 / 標準 / 全部）を `level` で制御
- キーボード操作（↑↓ 移動、→ 展開、← 閉じる）
- モバイルは 2 ペインではなくドリルダウン＋パンくず
- 葉に「もっと細かく」（必要時のみ遅延生成）
- 別解は根の兄弟としてタブに（因数分解 / 解の公式 / 平方完成）
- 中間形を省略しない（`x·x+x·2+5·x+5·2` を飛ばすと「なぜそうなるか」が消える）

### レベル設定

「中学 / 高校」で使える戦術を制限できるようにすると、解法の選択自体が変わる。後から入れると分岐が散らかるので、戦術の選択部分に最初からフックを置く。

## 見送った機能

**証明支援**（条件とゴールを入れると証明方針が出る）は、汎用の自動定理証明に相当し難易度が桁違いなため見送った。将来やるなら以下の順が現実的。

1. 反例チェッカー（「その命題は偽です。反例: n=4」）— 反例は代入して検証できるので嘘をつかない
2. 定理検索＋証明テンプレート（帰納法・背理法・対偶などの型）
3. 分野を絞った記号的自動証明（幾何 or 不等式のどちらか 1 つ）
4. LLM で証明案を作り記号エンジンで検証するハイブリッド

いずれの場合も、**「証明」と言い切らず「方針・ヒント」として出す**、**検証済み / 未検証を UI で明示する**の 2 点は守る。もっともらしい誤証明を出すのは電卓アプリの信頼を根本から壊す。
